7. Blueprint and leading-model assessment
The blueprint is still the solution. It says to establish trustworthy, time-indexed evidence and honest out-of-sample
evaluation before optimizing a sophisticated forecast. This archive demonstrates why that order matters: a
superficially complete 211-race file fails basic stage and row semantics before any Bayesian layer is involved.
 Top-tier expectation
Current archive
Judgment
Immutable release identity
Two different archive hashes share v0.9.20
FAIL
Canonical, source-vintaged truth
Multiple ledgers; new Wikipedia scrape has no manifest or consumer
FAIL
Explicit election institutions
Formats are labeled but decisive stage, candidate roles, and caucus are not enforced
PARTIAL
Fold-pure backtesting
Core validation source unchanged; later-cycle access remains possible
FAIL
Deployment-equivalent ensemble scoring
Mean-only stack objective and whole-component draw mixture unchanged
FAIL
Nested uncertainty calibration
Covariance selection still uses the same fold grid it scores
FAIL
Fail-closed release controls
Master switch works; version-incoherent gates still pass
PARTIAL
What should not be copied from peer models
Do not chase peer probability outputs, visual similarity, or added predictors. The strongest lesson from The Economist,
FiveThirtyEight/Morris, Silver-style empirical discipline, and other serious forecasters is not a single formula. It is a reproducible chain
from inputs through uncertainty to scoring. Herd convergence cannot repair a wrong election stage or a future-contaminated fold.
BLUEPRINT ANSWER
Keep the blueprint and strengthen its closure rule. An item closes only when the implementation diff,
adversarial test, clean regeneration, downstream behavior, and immutable release manifest all agree.
